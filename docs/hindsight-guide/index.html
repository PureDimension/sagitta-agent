1. 先读：界面关键词

以下词义以当前开源版 Hindsight 1.0.0 为准。全文用“归纳认识”解释 Observation，用“专题答案”解释 Mental Model。

界面项／关键词它具体做什么例子、当前值与影响管理建议
Control Plane / 控制台供人查看、调试和管理记忆的网页。你正在打开的 9999 端口。API、后台 worker 和数据库承担实际处理。了解即可
Bank / 记忆库一套隔离的记忆空间，内部包含文档、事实、归纳认识、实体、页面和配置。项目 A 和项目 B 使用不同 Bank 时，检索和整理分别在各自库内进行。Agent 管普通库；默认库由我们保护
Document / 文档一次提交的来源材料，可是一段对话、一份文本或一个文件。把一轮工作的记录作为一份文档；document_id 用来持续定位这份材料。系统记录，Agent 可提交和维护
Chunk / 分块为处理长材料，将一份文档切出的片段。分块大小常按字符计；原文档和提取事实仍有来源关联。系统处理
Memory / Fact / 记忆单元／事实从材料中提取的一条可独立检索的信息。“Lin 因回调故障推迟发布。”这里“事实”表示一种记录类型，其真实性仍取决于来源和提取。Agent 可读取和纠正
World / 世界事实关于外部人物、项目、环境等的信息。“用户说项目将在周五发布”属于外部信息；仍应保留“用户说”这个来源。自动分类
Experience / 经历从记忆库所代表主体的视角记录其行动和交互。“我安排了一个验证任务。”编码技巧、管理经验都可能出现在多种记忆类型里。自动分类
Observation / 观察／归纳认识把相关事实综合后形成、可随新证据修订的认识。若干次工作结果共同支持“该项目发布前应验证回调”；结论带有来源。后台维护，Agent 使用
Consolidation / 整合／整理把事实与已有归纳认识对照，创建、修订或移除归纳认识的过程。新事实写入以后可以自动排队整理。系统自动
Mental Model / 心智模型／专题答案围绕一个固定问题生成并保存的答案。问题是“团队如何交接工作？”；保存一份可刷新答案。这里指内容对象。Agent 维护问题与范围
Knowledge Page / 知识页带目录位置的专题答案，正文通常是 Markdown 文档。“项目交接手册”页面，按设定问题从库中记忆持续生成。Agent 维护主题、依据和刷新
Source Query / 源查询生成或刷新专题答案时要回答的问题。“目前已确认哪些发布约定？说明适用范围和例外。”它决定页面讨论什么。Agent 可维护
Retain / 保留／写入接收材料，进行提取、存储、建立检索数据。点击添加文档或调用写入 API 都会进入这类流程。系统自动记录＋Agent 主动写入
Recall / 召回寻找与问题相关的记忆，返回材料供调用方使用。“找出上次发布失败的原因。”主要返回记忆和来源。Agent 与自动 hook 使用
Reflect / 反思／分析Hindsight 内部模型边查询记忆边分析，再生成回答。“根据过去几次交付，下一次应该注意什么？”它会调用模型，产生耗时和费用。Agent 按需使用
Entity / 实体材料中提到的人、项目、工具、地点或概念。“Lin”“Bluebird”“登录回调”。共同实体有助于关联记忆。系统提取
Graph / 图谱／关系图记忆及其实体、语义、时间、因果关联构成的检索结构。从“延期”关联到“回调故障”；星座布局是这部分数据的可视化。系统维护
Tag / 标签附在记忆上的字符串，可用于筛选。project:bluebird、kind:decision。标签名称及其一致性由使用方维护。插件统一，必要时 Agent 选择
Entity Label / 实体标签让提取器按预设字段识别分类值。规定 stage 只能取 planning / testing / released；识别结果可额外保存为普通标签。我们配置词表
Scope / 范围在这里常指一组标签共同确定的 observation 整理分区。同一 Bank 内 [project:A] 和 [project:A,session:1] 是不同的范围。插件统一
Shared / Global / 共享／全局在 observation 范围语境中，表示同一 Bank 内的无标签范围。共享范围可将来自不同会话标签的事实放到一起归纳。跨 Bank 的经验转移另由使用方调度。插件配置
Metadata / 元数据记录来源、标识等附加键值信息。source: task-123。一般记忆筛选主要通过 tags；metadata 不自动等价于标签过滤。插件自动补充
Context / 上下文一段材料发生的背景说明。“这是一次失败发布后的复盘。”它和模型本轮上下文窗口是两个不同位置的内容。写入时可选
Mission / 使命对某个后台操作的自然语言指导。提取使命、整理使命、Reflect 使命分别作用于三个环节；后文分别解释。我们审查和配置
Directive / 指令在 Hindsight 的 Reflect 提示中应用的规则。“区分明确要求和推测”。主 Agent 的授权检查由 Sagitta 执行层实施。我们管理
Strategy / 策略预先命名的一套局部处理配置。写入策略控制如何提取；整合策略控制匹配范围如何归纳。我们定义，Agent 按需要选择
Trigger / 触发器规定什么时候执行一次页面或专题答案刷新。整理后刷新、按 cron 刷新、手动刷新。系统策略，Agent 可申请刷新
Cron / 定时表达式用“分 时 日 月 周”五个位置描述计划。0 3 * * * 是每天 UTC 03:00，也就是北京时间 11:00。我们配置或批准预设
Budget / 预算本次检索或分析允许投入多大工作量。Recall 的高预算探索更多候选；Reflect 的高预算允许更多分析步骤。Agent 在上限内选择
Token / 令牌模型计算输入输出长度的单位。与汉字数、字符数没有固定一对一关系。分块大小 3000 指字符，max_tokens 指令牌。系统预算
Embedding / 向量把文本转成数字表示，用于寻找含义相近的内容。提问措辞与原文不完全相同时，向量检索可能仍能找到原文。我们配置模型
Reranker / 重排序器对已找到的候选，再判断它们与当前问题的相关程度。将多个检索分支合并的候选重新排序。结果仍受模型能力影响。我们配置
RRF / 排名融合按各检索分支中的排名合并候选的一种方法。某条记忆同时被多个分支排在前面，就可能获得更高融合分。系统处理
Proof Count / 证据数量归纳认识背后关联了多少来源事实。重复记录可能并不独立；这个数量本身不能验证结论，也不等于经验成效评分。查看依据时参考
Score / 分数当前查询下的排序信号。Recall 的相关性分数用来排候选；不能当成事实为真的概率。诊断使用
Fresh / Stale / 已同步／已过期根据范围内记忆写入与页面读取进度判断是否有待处理更新。已同步表示跟上了系统记录的更新进度；内容准确性仍需看证据。系统状态
Operation / 后台操作一次可查询进度的任务。写入、整理、刷新页面、导入等可能分别产生任务。系统跟踪
Trace / 追踪某次检索、分析或刷新怎样得出结果的记录。看它查了什么、用了哪些材料、消耗多少 token。诊断使用
Webhook / 事件通知指定事件发生后，服务向一个地址发送通知。写入完成、整理完成；自动注入仍由 Sagitta 的 hook 决定。系统接入
MCP / 工具协议Agent 连接外部工具的一种协议入口。Hindsight 也有 HTTP API；MCP 工具白名单只约束 MCP 入口。接入层维护
Override / Inherited / 覆盖／继承当前库单独设置一个值，或继续使用上级默认值。恢复继承会清除局部覆盖；其结果可能是启用，也可能是禁用。我们配置
BM25／全文搜索利用词项匹配寻找文本的检索分支。当前本地 native 后端使用 PostgreSQL 全文能力；UI 有时以 BM25 泛称该分支。了解即可
JSON／JSON SchemaJSON 是键值和列表构成的数据格式；Schema 描述允许的字段与类型。结构化输出模式可要求一个对象包含“结论”和“依据”字段。开发配置
Upsert／重新摄入同一 ID 已存在时更新，否则新增。重写相同 document_id 会按写入模式处理原有材料。来源管理
VLM／视觉模型能够读取图片等视觉输入的模型。文字模型和文件文字解析器并不自动获得视觉理解能力。我们配置

2. 把对象串起来：一份材料会走到哪里

一份来源材料进入某个 Bank，分块并提取事实；事实之间建立关联，后台归纳 observation；预先设置问题的专题答案和页面再从这些知识中生成。图结构横跨可检索记忆。

界面项／关键词它具体做什么例子、当前值与影响管理建议
文档 → 分块 → 事实保留材料与从中提取的信息之间的来源关系。一段对话可能提取多条事实；一次写入成功也可能提取出零条事实。自动执行
事实 → Observation积累支持、反对或补充材料，增量修订认识。新认识能被召回，也可以用于页面整理。自动执行
Observation → 知识页由源查询决定主题，将相关认识整理为可阅读文档。默认知识页只读 observation，采用增量刷新，并排除其他专题答案。自动执行；主题由使用方设置
Graph 与各层关系关联可以帮助检索找到相邻的记忆和相关证据。关系由提取与相似度等过程建立，需要保留对来源可靠性的判断。自动维护
Bank 与以上对象上述内容全部处在所属 Bank 的边界内。“主库＋项目库”联合召回由未来 sagitta-memory 分别查询后组合。插件与 Agent 管路由

5. 记忆页面与记忆详情

这是检查“系统到底记住了什么”的主要入口；页面中的筛选和 Recall 的相关性检索用途不同。

界面项／关键词它具体做什么例子、当前值与影响管理建议
世界／经历／观察切换要查看的记忆类型。检查提取错误看世界／经历；检查总结是否跑偏看观察。日常检查
文本筛选、标签筛选按已存文本或标签缩小列表。用于查全某一标签下的条目；与一句问题的语义召回不同。日常使用
有效／已失效查看当前参与召回的记录，或审计归档中的失效记录。已失效仍保留，可恢复。Agent 可申请纠正
表格、时间线、星座视图同一批数据的三种展示。表格看字段；时间线看事件顺序；星座看关联。缺少事件时间的记忆可能只在表格可见。查看即可
观察范围、按范围分组查看 observation 属于哪个标签组合。可判断是否因会话标签过细而产生许多相似但隔离的总结。插件配置；人工检查
正文、上下文、实体、标签、元数据分别展示记住的内容、材料背景、涉及对象、筛选标签和附加来源信息。正文可能是从原文改写出的提取结果。Agent 读取
发生时间、提及时间、创建时间分别是事件日期、记录中提到该信息的时间、写入数据库的时间。排查“过去说的”“现在有效的”时，要看时间字段及正文条件。Agent 读取
源记忆／证据数量归纳认识背后的事实及其数量。点查看向下追溯；核对不同来源是否实际独立。Agent 与人工核对
分块／文档打开提取这一事实时的原始片段或完整材料。用于发现提取遗漏上下文、条件、否定等情况。Agent 按需展开
历史观察内容历次归纳更新的记录。展示派生认识如何变；单条事实的完整版本保留能力应按具体接口判断。诊断使用
创建来源／整合来源跳到产生这条记录的模型调用信息。用于看提取或整理环节使用了什么材料。诊断使用
整理 → 编辑纠正原始事实文字、上下文、类型、发生起止日期、实体等。会更新相关索引，并使受影响的派生 observation 重新整理；原始文档保留原样。Agent 可维护事实
整理 → 失效／恢复／原因将错误或不再适用的事实移出当前召回，保留原因；需要时恢复。重新提取原文会重新产生事实，可能覆盖事实层的人工修订；应同时判断是否需要修正文档。Agent 可维护，审计记录由系统保留
归纳认识的纠正先检查支持事实，纠正错误来源，再申请重新整理。观察作为派生结果，普通事实编辑接口只支持 world / experience。Agent 按来源维护

6. 知识库 → 知识页
