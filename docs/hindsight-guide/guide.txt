Hindsight 1.0.0 中文界面对照手册
核对日期：2026-10-16
按顺序阅读：关键词 → 每个页面 → 每项配置 → 与 Sagitta 的分工。
全文可用编辑器的查找功能搜索界面名称。HTML 版带目录、折叠和搜索。

1. 先读：界面关键词
================================================
以下词义以当前开源版 Hindsight 1.0.0 为准。全文用“归纳认识”解释 Observation，用“专题答案”解释 Mental Model。

【Control Plane / 控制台】
含义：供人查看、调试和管理记忆的网页。
例子与影响：你正在打开的 9999 端口。API、后台 worker 和数据库承担实际处理。
管理建议：了解即可

【Bank / 记忆库】
含义：一套隔离的记忆空间，内部包含文档、事实、归纳认识、实体、页面和配置。
例子与影响：项目 A 和项目 B 使用不同 Bank 时，检索和整理分别在各自库内进行。
管理建议：Agent 管普通库；默认库由我们保护

【Document / 文档】
含义：一次提交的来源材料，可是一段对话、一份文本或一个文件。
例子与影响：把一轮工作的记录作为一份文档；document_id 用来持续定位这份材料。
管理建议：系统记录，Agent 可提交和维护

【Chunk / 分块】
含义：为处理长材料，将一份文档切出的片段。
例子与影响：分块大小常按字符计；原文档和提取事实仍有来源关联。
管理建议：系统处理

【Memory / Fact / 记忆单元／事实】
含义：从材料中提取的一条可独立检索的信息。
例子与影响：“Lin 因回调故障推迟发布。”这里“事实”表示一种记录类型，其真实性仍取决于来源和提取。
管理建议：Agent 可读取和纠正

【World / 世界事实】
含义：关于外部人物、项目、环境等的信息。
例子与影响：“用户说项目将在周五发布”属于外部信息；仍应保留“用户说”这个来源。
管理建议：自动分类

【Experience / 经历】
含义：从记忆库所代表主体的视角记录其行动和交互。
例子与影响：“我安排了一个验证任务。”编码技巧、管理经验都可能出现在多种记忆类型里。
管理建议：自动分类

【Observation / 观察／归纳认识】
含义：把相关事实综合后形成、可随新证据修订的认识。
例子与影响：若干次工作结果共同支持“该项目发布前应验证回调”；结论带有来源。
管理建议：后台维护，Agent 使用

【Consolidation / 整合／整理】
含义：把事实与已有归纳认识对照，创建、修订或移除归纳认识的过程。
例子与影响：新事实写入以后可以自动排队整理。
管理建议：系统自动

【Mental Model / 心智模型／专题答案】
含义：围绕一个固定问题生成并保存的答案。
例子与影响：问题是“团队如何交接工作？”；保存一份可刷新答案。这里指内容对象。
管理建议：Agent 维护问题与范围

【Knowledge Page / 知识页】
含义：带目录位置的专题答案，正文通常是 Markdown 文档。
例子与影响：“项目交接手册”页面，按设定问题从库中记忆持续生成。
管理建议：Agent 维护主题、依据和刷新

【Source Query / 源查询】
含义：生成或刷新专题答案时要回答的问题。
例子与影响：“目前已确认哪些发布约定？说明适用范围和例外。”它决定页面讨论什么。
管理建议：Agent 可维护

【Retain / 保留／写入】
含义：接收材料，进行提取、存储、建立检索数据。
例子与影响：点击添加文档或调用写入 API 都会进入这类流程。
管理建议：系统自动记录＋Agent 主动写入

【Recall / 召回】
含义：寻找与问题相关的记忆，返回材料供调用方使用。
例子与影响：“找出上次发布失败的原因。”主要返回记忆和来源。
管理建议：Agent 与自动 hook 使用

【Reflect / 反思／分析】
含义：Hindsight 内部模型边查询记忆边分析，再生成回答。
例子与影响：“根据过去几次交付，下一次应该注意什么？”它会调用模型，产生耗时和费用。
管理建议：Agent 按需使用

【Entity / 实体】
含义：材料中提到的人、项目、工具、地点或概念。
例子与影响：“Lin”“Bluebird”“登录回调”。共同实体有助于关联记忆。
管理建议：系统提取

【Graph / 图谱／关系图】
含义：记忆及其实体、语义、时间、因果关联构成的检索结构。
例子与影响：从“延期”关联到“回调故障”；星座布局是这部分数据的可视化。
管理建议：系统维护

【Tag / 标签】
含义：附在记忆上的字符串，可用于筛选。
例子与影响：project:bluebird、kind:decision。标签名称及其一致性由使用方维护。
管理建议：插件统一，必要时 Agent 选择

【Entity Label / 实体标签】
含义：让提取器按预设字段识别分类值。
例子与影响：规定 stage 只能取 planning / testing / released；识别结果可额外保存为普通标签。
管理建议：我们配置词表

【Scope / 范围】
含义：在这里常指一组标签共同确定的 observation 整理分区。
例子与影响：同一 Bank 内 [project:A] 和 [project:A,session:1] 是不同的范围。
管理建议：插件统一

【Shared / Global / 共享／全局】
含义：在 observation 范围语境中，表示同一 Bank 内的无标签范围。
例子与影响：共享范围可将来自不同会话标签的事实放到一起归纳。跨 Bank 的经验转移另由使用方调度。
管理建议：插件配置

【Metadata / 元数据】
含义：记录来源、标识等附加键值信息。
例子与影响：source: task-123。一般记忆筛选主要通过 tags；metadata 不自动等价于标签过滤。
管理建议：插件自动补充

【Context / 上下文】
含义：一段材料发生的背景说明。
例子与影响：“这是一次失败发布后的复盘。”它和模型本轮上下文窗口是两个不同位置的内容。
管理建议：写入时可选

【Mission / 使命】
含义：对某个后台操作的自然语言指导。
例子与影响：提取使命、整理使命、Reflect 使命分别作用于三个环节；后文分别解释。
管理建议：我们审查和配置

【Directive / 指令】
含义：在 Hindsight 的 Reflect 提示中应用的规则。
例子与影响：“区分明确要求和推测”。主 Agent 的授权检查由 Sagitta 执行层实施。
管理建议：我们管理

【Strategy / 策略】
含义：预先命名的一套局部处理配置。
例子与影响：写入策略控制如何提取；整合策略控制匹配范围如何归纳。
管理建议：我们定义，Agent 按需要选择

【Trigger / 触发器】
含义：规定什么时候执行一次页面或专题答案刷新。
例子与影响：整理后刷新、按 cron 刷新、手动刷新。
管理建议：系统策略，Agent 可申请刷新

【Cron / 定时表达式】
含义：用“分 时 日 月 周”五个位置描述计划。
例子与影响：0 3 * * * 是每天 UTC 03:00，也就是北京时间 11:00。
管理建议：我们配置或批准预设

【Budget / 预算】
含义：本次检索或分析允许投入多大工作量。
例子与影响：Recall 的高预算探索更多候选；Reflect 的高预算允许更多分析步骤。
管理建议：Agent 在上限内选择

【Token / 令牌】
含义：模型计算输入输出长度的单位。
例子与影响：与汉字数、字符数没有固定一对一关系。分块大小 3000 指字符，max_tokens 指令牌。
管理建议：系统预算

【Embedding / 向量】
含义：把文本转成数字表示，用于寻找含义相近的内容。
例子与影响：提问措辞与原文不完全相同时，向量检索可能仍能找到原文。
管理建议：我们配置模型

【Reranker / 重排序器】
含义：对已找到的候选，再判断它们与当前问题的相关程度。
例子与影响：将多个检索分支合并的候选重新排序。结果仍受模型能力影响。
管理建议：我们配置

【RRF / 排名融合】
含义：按各检索分支中的排名合并候选的一种方法。
例子与影响：某条记忆同时被多个分支排在前面，就可能获得更高融合分。
管理建议：系统处理

【Proof Count / 证据数量】
含义：归纳认识背后关联了多少来源事实。
例子与影响：重复记录可能并不独立；这个数量本身不能验证结论，也不等于经验成效评分。
管理建议：查看依据时参考

【Score / 分数】
含义：当前查询下的排序信号。
例子与影响：Recall 的相关性分数用来排候选；不能当成事实为真的概率。
管理建议：诊断使用

【Fresh / Stale / 已同步／已过期】
含义：根据范围内记忆写入与页面读取进度判断是否有待处理更新。
例子与影响：已同步表示跟上了系统记录的更新进度；内容准确性仍需看证据。
管理建议：系统状态

【Operation / 后台操作】
含义：一次可查询进度的任务。
例子与影响：写入、整理、刷新页面、导入等可能分别产生任务。
管理建议：系统跟踪

【Trace / 追踪】
含义：某次检索、分析或刷新怎样得出结果的记录。
例子与影响：看它查了什么、用了哪些材料、消耗多少 token。
管理建议：诊断使用

【Webhook / 事件通知】
含义：指定事件发生后，服务向一个地址发送通知。
例子与影响：写入完成、整理完成；自动注入仍由 Sagitta 的 hook 决定。
管理建议：系统接入

【MCP / 工具协议】
含义：Agent 连接外部工具的一种协议入口。
例子与影响：Hindsight 也有 HTTP API；MCP 工具白名单只约束 MCP 入口。
管理建议：接入层维护

【Override / Inherited / 覆盖／继承】
含义：当前库单独设置一个值，或继续使用上级默认值。
例子与影响：恢复继承会清除局部覆盖；其结果可能是启用，也可能是禁用。
管理建议：我们配置

【BM25／全文搜索】
含义：利用词项匹配寻找文本的检索分支。
例子与影响：当前本地 native 后端使用 PostgreSQL 全文能力；UI 有时以 BM25 泛称该分支。
管理建议：了解即可

【JSON／JSON Schema】
含义：JSON 是键值和列表构成的数据格式；Schema 描述允许的字段与类型。
例子与影响：结构化输出模式可要求一个对象包含“结论”和“依据”字段。
管理建议：开发配置

【Upsert／重新摄入】
含义：同一 ID 已存在时更新，否则新增。
例子与影响：重写相同 document_id 会按写入模式处理原有材料。
管理建议：来源管理

【VLM／视觉模型】
含义：能够读取图片等视觉输入的模型。
例子与影响：文字模型和文件文字解析器并不自动获得视觉理解能力。
管理建议：我们配置

核对依据：https://hindsight.vectorize.io/faq

2. 把对象串起来：一份材料会走到哪里
================================================
一份来源材料进入某个 Bank，分块并提取事实；事实之间建立关联，后台归纳 observation；预先设置问题的专题答案和页面再从这些知识中生成。图结构横跨可检索记忆。

【文档 → 分块 → 事实】
含义：保留材料与从中提取的信息之间的来源关系。
例子与影响：一段对话可能提取多条事实；一次写入成功也可能提取出零条事实。
管理建议：自动执行

【事实 → Observation】
含义：积累支持、反对或补充材料，增量修订认识。
例子与影响：新认识能被召回，也可以用于页面整理。
管理建议：自动执行

【Observation → 知识页】
含义：由源查询决定主题，将相关认识整理为可阅读文档。
例子与影响：默认知识页只读 observation，采用增量刷新，并排除其他专题答案。
管理建议：自动执行；主题由使用方设置

【Graph 与各层关系】
含义：关联可以帮助检索找到相邻的记忆和相关证据。
例子与影响：关系由提取与相似度等过程建立，需要保留对来源可靠性的判断。
管理建议：自动维护

【Bank 与以上对象】
含义：上述内容全部处在所属 Bank 的边界内。
例子与影响：“主库＋项目库”联合召回由未来 sagitta-memory 分别查询后组合。
管理建议：插件与 Agent 管路由

核对依据：https://hindsight.vectorize.io/faq

3. 全局导航、所有记忆库与新建记忆库
================================================
顶部选择的是当前操作目标；切换 Bank 后，本次网页检索、配置和文档管理都作用于所选库。

【所有记忆库／顶部选择器】
含义：查看库列表，或切换当前库。
例子与影响：列表中的记忆数量是数据规模，不代表记忆能力或成熟度。
管理建议：Agent 可管理普通库

【搜索记忆库】
含义：按库标识或名称定位库。
例子与影响：用于库越来越多时找到项目库。
管理建议：日常使用

【库名称、ID、最近活动、创建时间】
含义：名称供人辨认，ID 供 API 稳定定位；两种时间分别表示活动和建立时间。
例子与影响：改显示名称与修改底层 ID 是不同操作。
管理建议：Agent 可命名与描述普通库

【复选框／批量删除】
含义：选择多个库后执行批量操作。
例子与影响：删除 Bank 会移除该库数据，属于管理操作。
管理建议：人工管理

【创建新记忆库】
含义：填库 ID 和显示名称，建立隔离空间。
例子与影响：项目 ID 应稳定，跨会话继续用同一项目库。
管理建议：Agent 在既定模板下创建

【从模板导入／模板清单】
含义：以 JSON 应用 Bank 配置、专题答案和指令等初始设置。
例子与影响：导入的是配置模板；完整历史数据有单独的导入导出入口。
管理建议：我们维护模板

【添加文档】
含义：向当前 Bank 提交文本、文件或组合内容。
例子与影响：完整字段见“添加文档”章节。
管理建议：Agent 可写入

【展开侧边栏、深浅色、切换语言、GitHub】
含义：导航显示、界面外观、显示语言和上游源码入口。
例子与影响：切换 UI 中文只改变界面文字，embedding/reranker 模型另行配置。
管理建议：界面偏好

核对依据：https://github.com/vectorize-io/hindsight/blob/v1.0.0/hindsight-control-plane/src/components/banks-overview.tsx

4. 首页
================================================
首页主要展示状态与入口。

【记忆星座图】
含义：将一部分记忆节点及关联画成星座；可缩放、平移、悬停、点击。
例子与影响：首页有显示数量上限；完整检查进入“记忆”。节点布局、亮度和连线密度用于观察结构。
管理建议：查看即可

【查看全部】
含义：跳到相应完整列表。
例子与影响：星座图旁的查看全部进入记忆页；知识页和文档各有自己的入口。
管理建议：导航

【暂停、全屏、分享】
含义：控制图的动画、显示方式，或导出 SVG 图像。
例子与影响：图像导出保存的是可视化，不等同于导出数据库。
管理建议：查看即可

【知识页、最近文档】
含义：最近维护的生成页面、最近写入的来源材料。
例子与影响：页面和原始文档分别展示。
管理建议：查看即可

【记忆、文档、链接数量】
含义：记录个数、来源材料个数、关联规模。
例子与影响：数量增长能反映数据进入系统，质量应通过具体召回和依据判断。
管理建议：查看即可

【记忆构成／链接类型】
含义：按世界、经历、观察分类记忆；按时间、语义、实体、因果分类关系。
例子与影响：分类占比展示现状，没有必须达到的理想比例。
管理建议：查看即可

【1h—90d；摄入／提及／发生时间】
含义：按观察窗口和选定时间字段看记录分布。
例子与影响：摄入是何时进库；提及是何时被说起；发生是事情本身何时发生。
管理建议：查看即可

核对依据：https://github.com/vectorize-io/hindsight/blob/v1.0.0/hindsight-control-plane/src/components/home-view.tsx

5. 记忆页面与记忆详情
================================================
这是检查“系统到底记住了什么”的主要入口；页面中的筛选和 Recall 的相关性检索用途不同。

【世界／经历／观察】
含义：切换要查看的记忆类型。
例子与影响：检查提取错误看世界／经历；检查总结是否跑偏看观察。
管理建议：日常检查

【文本筛选、标签筛选】
含义：按已存文本或标签缩小列表。
例子与影响：用于查全某一标签下的条目；与一句问题的语义召回不同。
管理建议：日常使用

【有效／已失效】
含义：查看当前参与召回的记录，或审计归档中的失效记录。
例子与影响：已失效仍保留，可恢复。
管理建议：Agent 可申请纠正

【表格、时间线、星座视图】
含义：同一批数据的三种展示。
例子与影响：表格看字段；时间线看事件顺序；星座看关联。缺少事件时间的记忆可能只在表格可见。
管理建议：查看即可

【观察范围、按范围分组】
含义：查看 observation 属于哪个标签组合。
例子与影响：可判断是否因会话标签过细而产生许多相似但隔离的总结。
管理建议：插件配置；人工检查

【正文、上下文、实体、标签、元数据】
含义：分别展示记住的内容、材料背景、涉及对象、筛选标签和附加来源信息。
例子与影响：正文可能是从原文改写出的提取结果。
管理建议：Agent 读取

【发生时间、提及时间、创建时间】
含义：分别是事件日期、记录中提到该信息的时间、写入数据库的时间。
例子与影响：排查“过去说的”“现在有效的”时，要看时间字段及正文条件。
管理建议：Agent 读取

【源记忆／证据数量】
含义：归纳认识背后的事实及其数量。
例子与影响：点查看向下追溯；核对不同来源是否实际独立。
管理建议：Agent 与人工核对

【分块／文档】
含义：打开提取这一事实时的原始片段或完整材料。
例子与影响：用于发现提取遗漏上下文、条件、否定等情况。
管理建议：Agent 按需展开

【历史】
含义：观察内容历次归纳更新的记录。
例子与影响：展示派生认识如何变；单条事实的完整版本保留能力应按具体接口判断。
管理建议：诊断使用

【创建来源／整合来源】
含义：跳到产生这条记录的模型调用信息。
例子与影响：用于看提取或整理环节使用了什么材料。
管理建议：诊断使用

【整理 → 编辑】
含义：纠正原始事实文字、上下文、类型、发生起止日期、实体等。
例子与影响：会更新相关索引，并使受影响的派生 observation 重新整理；原始文档保留原样。
管理建议：Agent 可维护事实

【整理 → 失效／恢复／原因】
含义：将错误或不再适用的事实移出当前召回，保留原因；需要时恢复。
例子与影响：重新提取原文会重新产生事实，可能覆盖事实层的人工修订；应同时判断是否需要修正文档。
管理建议：Agent 可维护，审计记录由系统保留

【归纳认识的纠正】
含义：先检查支持事实，纠正错误来源，再申请重新整理。
例子与影响：观察作为派生结果，普通事实编辑接口只支持 world / experience。
管理建议：Agent 按来源维护

7. 知识库 → 心智模型
================================================
普通心智模型默认按需刷新、完整生成；知识页有更偏文档维护的默认值。

【列表／表格／详情】
含义：按名称、ID、源查询、刷新时间等查看保存的专题答案。
例子与影响：一个模型可以回答“我与用户目前的协作约定是什么”。
管理建议：Agent 管理

【添加、名称、可选 ID、源查询、最大令牌数】
含义：定义专题答案的身份、问题和内容长度。

管理建议：Agent 在预算范围内管理

【选项】
含义：规定何时刷新、怎么改写、读取哪些材料和高级预算。

管理建议：Agent 使用受控预设

【已读至、最近刷新、下次刷新、已过期】

含义：后台可能先重试；最终失败后自动刷新可暂停，成功的手动刷新可恢复。
例子与影响：应查看任务和失败原因，避免一直使用旧内容。
管理建议：系统监控；Agent 可反馈

【清除内容】
含义：保留对象定义，移除已生成正文，下一次刷新从头生成。
例子与影响：用于重新合成专题答案；来源事实另行保存。
管理建议：管理与修复

【删除模型】
含义：移除定义和保存的专题答案。
例子与影响：知识页关联的模型应连同目录关系在相应页面入口管理。
管理建议：限定管理

含义：查看设置、生成依据与版本演变。
例子与影响：追踪是否保留受开关和保留策略影响。
管理建议：诊断使用

8. 页面与心智模型：全部刷新选项
================================================
这套表单既用于单个专题答案，也用于 Bank 的“新知识页默认设置”。页面级设置作用于该页面；Bank 默认设置主要给之后新建的页面提供初始值。

【名称／ID／源查询】
含义：定义对象身份与生成问题。
例子与影响：源查询改变后，下一次生成可能完整重建。
管理建议：Agent 维护主题

【最大令牌数】
含义：限制生成正文的内容预算。
例子与影响：与本次检索读多少资料分开；正文太短可能省略重要条件。
管理建议：Agent 在上限内选择

【何时刷新：有新记忆时】
含义：在相关 observation 整理之后触发自动刷新。
例子与影响：有新资料进入该范围才推动更新；服务和 worker 要处于运行状态。
管理建议：系统策略

【何时刷新：按计划】
含义：按 cron 检查并刷新过期内容。
例子与影响：通常没有相关变化会跳过生成；按计划和整理后自动触发是两个替代选项。
管理建议：系统策略

【何时刷新：仅手动】
含义：通过界面或 API 主动要求时刷新。
例子与影响：适合低频使用、需要精确控制开销的专题。
管理建议：Agent 按需申请

【Cron 表达式与预设】
含义：每小时、每天、每周等计划，使用 UTC。
例子与影响：0 3 * * * 对应北京时间每天 11:00；界面可预览后续触发时间。
管理建议：我们设置

【最小刷新间隔（秒）】
含义：两次自动刷新至少隔多久；窗口内多次触发合并成一次待执行任务。
例子与影响：留空继承；0 表示无间隔下限；显式手动刷新可立即运行。
管理建议：我们定预算

【如何重写：增量 delta】
含义：在已有正文上做局部更新，尽量保留未变化部分。
例子与影响：首次生成或源查询改变时可能转为完整生成。
管理建议：通常先用页面默认值

【如何重写：完全重写 full】
含义：每次从检索到的材料重新生成全文。
例子与影响：有利于重新组织，但文字和结构可能发生更大变化。
管理建议：依用途选择

【读取什么：事实类型】
含义：选择世界事实、经历、归纳认识中的哪些作为来源。
例子与影响：普通模型默认可读全部；知识页默认读 observation。
管理建议：Agent 用预设

【标签】
含义：限定本专题覆盖的记忆来源，并影响其在 Reflect 中的可见范围。
例子与影响：给页面新增一个源材料没有的标签，可能导致生成“没有资料”。
管理建议：插件统一标签，Agent 可选已有值

【标签匹配】
含义：决定任意、全部、严格或完全匹配，详见标签章节。
例子与影响：页面有标签时默认采用 all_strict；不同入口默认值可能不同。
管理建议：插件给出预设

【排除所有心智模型】
含义：刷新时只从事实／归纳认识获取依据，跳过其他生成答案和页面。
例子与影响：有助于减少生成摘要互相引用形成循环支持。知识页默认启用。
管理建议：通常保留知识页默认值

【高级：排除心智模型 ID】
含义：只跳过指定的生成答案。
例子与影响：适用于允许引用部分专题、排除某份有问题的旧总结。
管理建议：高级维护

【高级：包含分块】
含义：检索时把原始片段一起提供给刷新流程。
例子与影响：可看到更多上下文，同时增加输入长度。留空继承。
管理建议：按材料需要设置

【高级：召回最大 token 数】
含义：刷新内部召回返回的事实材料预算。
例子与影响：调大能带入更多候选材料，也增加模型输入成本。
管理建议：我们定上限

【高级：召回分块最大 token 数】
含义：给原始片段的独立长度预算。
例子与影响：在需要核对原文时使用，和事实预算分别设置。
管理建议：我们定上限

【高级：观察最大令牌数】
含义：刷新分析时，一次观察检索允许带入的文字预算。
例子与影响：越小越省上下文，也可能缺少相关认识。
管理建议：我们定预算

【高级：观察实体】
含义：是否附上 observation 关联的规范实体名称。
例子与影响：能帮助识别别名所指对象，但增加上下文占用。
管理建议：按实测设置

【高级：刷新预算 low / mid / high】
含义：控制本次生成允许的检索分析步数。
例子与影响：当前实现按服务迭代上限缩放：低约减半、中保持、高约加倍；实际调用可提前结束。
管理建议：Agent 在上限内选择

【高级：标签组 JSON】
含义：用 and / or / not 等组合更复杂的筛选条件。
例子与影响：适合“项目 A 且（决策或结果）”。有复合表达式时按该表达式限定来源。
管理建议：插件生成，普通 AI 使用简化条件

【高级：结构化输出模式】
含义：要求额外返回满足指定 JSON 结构的结果。
例子与影响：如列出 decision、evidence、open_questions；适合程序读取。
管理建议：我们定义结构

【高级：保留刷新追踪】
含义：保存最近一次刷新怎样检索和修改的诊断信息。
例子与影响：有助于检查后台整理；不是无限期保留全部模型对话。
管理建议：调试时启用

【构建模式：可视化／代码】
含义：用字段编辑器或 JSON Schema 定义输出结构。
例子与影响：字段名、说明、类型、必填；对象可嵌套，数组需定义元素。复杂结构用代码模式。
管理建议：接口设计与调试

【取消、应用、保存、恢复继承】
含义：取消放弃本次表单；应用把结构填回上层；保存向服务提交；恢复继承清除局部设置。
例子与影响：部分对话框有独立保存按钮，应以具体界面状态判断是否已写入。
管理建议：人工使用

9. 标签匹配与观察范围：同一个词出现在不同地方
================================================
标签筛选决定“查哪些记录”；observation_scopes 决定“哪些记录放在一起形成归纳认识”。它们都使用标签，但承担不同职责。

【any / 任意（含未标记）】
含义：匹配任意所列标签，并允许无标签记忆参与。
例子与影响：查 A 或 B 时，无标签记录也可能返回。
管理建议：查询时选择

【all / 全部（含未标记）】
含义：要求带标签的候选满足全部所列标签，同时允许无标签记录。
例子与影响：需要“严格属于项目 A”时应考虑严格模式。
管理建议：查询时选择

【any_strict / 任意（严格）】
含义：至少匹配一个所列标签，排除无标签记录。
例子与影响：A 或 B；空标签记录被排除。
管理建议：查询时选择

【all_strict / 全部（严格）】
含义：同时拥有全部所列标签，排除无标签记录；可以有其他标签。
例子与影响：指定 project:A 与 kind:decision，只取同时包含两者的记录。
管理建议：页面有标签时的默认行为

【exact / 完全匹配】
含义：候选标签集合与指定集合完全相同。
例子与影响：[A,B] 不匹配 [A,B,C]；空集合可选择无标签范围。
管理建议：高级查询

【标签组 JSON】
含义：将多个标签条件组合为布尔表达式。
例子与影响：用于比任意／全部更复杂的范围；各入口按其 schema 使用。
管理建议：插件或调试

【观察范围：Combined】
含义：把本次文档全部标签合成一个范围。
例子与影响：标签 A、B → [A,B]。这是 API 未指定范围时的默认方式。
管理建议：插件统一

【观察范围：按标签 per_tag】
含义：每个标签单独形成范围。
例子与影响：A、B → [A] 和 [B]，可能为同一材料形成多份归纳。
管理建议：插件统一

【观察范围：所有组合】
含义：为标签的每个非空子集建立范围。
例子与影响：A、B → [A]、[B]、[A,B]；标签增多时范围数量增长很快。
管理建议：按明确需要启用

【观察范围：共享 shared】
含义：统一归到本 Bank 的无标签范围，原始事实仍可保留来源标签。
例子与影响：即使 session:1 与 session:2 不同，也可参与同一范围的归纳。
管理建议：适合跨会话归纳，需结合范围设计

【观察范围：自定义】
含义：明确列出要参与整理的标签组合。
例子与影响：界面每行一个范围，行内用逗号列标签。
管理建议：高级配置

【实体标签勾选“+ 标签”】

【操作 → 运行整合】

16. 配置页通用规则：先理解保存与继承
================================================
当前页面每个分区通常有自己的“保存更改”。更改一个分区后，应看该分区的保存状态。记忆防护页使用自动保存，单独说明。

【服务器默认值／继承】
含义：使用上级的生效值。
例子与影响：服务器默认现在启用，继承也启用；上级将来改变后该库会跟随。
管理建议：先保持默认

【库级覆盖】
含义：当前 Bank 固定设置一个值。
例子与影响：需要项目库行为与默认模板不同才设覆盖。
管理建议：我们配置

【恢复继承值】
含义：删除本 Bank 对该字段或分区的覆盖。
例子与影响：它与“关闭功能”是不同含义。
管理建议：我们配置

【留空、0、-1】
含义：分别可能表示继承、零、无限制或其他特殊值，按每个字段解释。
例子与影响：例如最小刷新间隔 0 是不设频率下限；观察上限 -1 是无限制。
管理建议：按字段说明使用

【三种使命】
含义：Retain 决定挑什么信息；观察使命决定怎么归纳；Reflect 使命决定怎样分析回答。
例子与影响：Retain 使命补充默认规则；观察使命和自定义提取规则可以替换内置部分。
管理建议：核心规则由我们审查

【配置修改与历史数据】
含义：许多设置控制之后的处理。
例子与影响：换提取模式后，旧文档需重新处理才会重新提取；现有页面也有自己的刷新状态。
管理建议：按影响范围安排迁移

17. 配置 → Retain：每项含义
================================================
这个分区决定从材料中记住哪些信息；它不会决定 DSH 在什么时候把材料提交过来。

【默认策略】
含义：调用方没有指定 strategy 时采用哪套写入设置。
例子与影响：命名策略可以用于不同材料类型；未定义时用默认设置。
管理建议：我们设模板，Agent 可选预设

【默认／添加策略／策略名称】
含义：创建可复用的一套局部提取设置。
例子与影响：命名 daily-log 后可在写入时选择；名称应与调用方一致。
管理建议：我们维护

【策略内的继承与覆盖】
含义：命名策略只改需要不同的项，其他项沿用默认。
例子与影响：删除策略前应检查谁还在引用它。
管理建议：我们维护

【提取模式：简洁 concise】
含义：选择较值得长期保存的信息。
例子与影响：噪声通常少些，但可能遗漏你希望保留的细节。
管理建议：初始可保留

【提取模式：详尽 verbose】
含义：更积极保留细节。
例子与影响：材料更多、提取调用输出更长；仍受模型能力和提示限制。
管理建议：通过样本比较后决定

【提取模式：逐字 verbatim】
含义：将每个分块的原文作为一条记忆，模型仍可提取相关元信息。
例子与影响：更接近保留原话；检索单位也变得更大。
管理建议：特定资料用途

【提取模式：分块 chunks】
含义：直接以分块保存文字，跳过 LLM 事实提取。
例子与影响：自动实体能力与 observation／Reflect 的可用性还取决于服务配置。
管理建议：特定资料或无 LLM 测试

【提取模式：自定义 custom】
含义：使用自行编写的事实提取说明。
例子与影响：有明确提取目标时可用；需要用测试样本检查遗漏与误提取。
管理建议：我们审查

【自定义提取提示词】
含义：custom 模式下替换默认提取规则的内容。
例子与影响：普通模式下此字段不作为该模式的提取规则。
管理建议：我们审查

【分块大小】
含义：长材料按多少字符切分，当前默认 3000。
例子与影响：块更小可能拆散因果上下文；块更大则单次输入更长。
管理建议：先默认，按材料调试

【结构化分块大小】
含义：允许一条完整对话轮次或 JSONL 记录保持完整的更大字符限额。
例子与影响：留空沿用普通分块大小；适合避免一条记录被中途截开。
管理建议：我们配置

【使命】
含义：说明这个库特别需要保留什么。
例子与影响：可写“保留明确约定、决策依据与实际结果，保留适用条件”。补充内置规则。
管理建议：我们审查

【自由形式实体】
含义：允许识别词表之外的人、项目、工具等对象。
例子与影响：关闭后主要依赖配置的实体标签；完全未设词表时会失去很多实体关联。
管理建议：初始保留启用

【实体标签／添加标签】
含义：预设希望提取的分类字段。
例子与影响：例如 outcome 为 success / failure；具体嵌套项见下一章。
管理建议：我们维护词表

【测试 retain 提取】
含义：提交样本，查看模型会提取什么；不会写入正式记忆，但会实际调用模型。
例子与影响：用同一份带例外、纠正、猜测的对话比较不同设置。
管理建议：调试使用

【测试器：提示词／测试数据／策略／运行／结果】
含义：看实际发给模型的消息顺序，输入测试材料和策略，检查事实、实体、时间、分块和用时。
例子与影响：可见文字变化与保存到库配置的动作分开；以界面保存提示为准。
管理建议：调试使用

【提示词预览：区块／原文／编辑／保存】
含义：显示内置指令、库配置、实体规则等怎样组合成最终提示。
例子与影响：预览中的一些编辑可以保存真实配置；部分项属于服务级。
管理建议：我们调试和审查

18. 配置 → 实体标签：展开后的每一项
================================================
实体标签提供一套由我们定义的提取结构。初始可以留空，先观察自由实体和默认提取是否足够。

【字段名／key】
含义：分类维度的稳定名称。
例子与影响：如 outcome、stage；会形成 key:value 形式的实体名称。
管理建议：我们定义

【描述／提取器提示：提取什么】
含义：告诉模型从材料中找哪种信息。
例子与影响：“本次验证的实际结果，忽略尚未执行的预期。”
管理建议：我们定义

【类型：单值 value】
含义：在固定候选中选一个值。
例子与影响：stage 选 planning、testing 或 released。
管理建议：我们定义

【类型：多值 multi-values】
含义：可从固定候选中选多个值。
例子与影响：issues 选 callback、login、database 中适用的多个。
管理建议：我们定义

【类型：文本 text】
含义：让模型写一个开放文本值。
例子与影响：值很灵活，但近义表述可能分散成多个名称。
管理建议：按实际需要

【类型：多文本 multi-text】
含义：从材料提取多个开放值。
例子与影响：如一个事物的别名、简称和正式名称。
管理建议：按实际需要

【类型：映射 map】
含义：把一个字段展开为多级子字段。
例子与影响：person 内有 name、role；系统会将路径和值展开成标签实体。
管理建议：高级结构

【候选值／值描述／何时选择此值】
含义：指定允许的枚举及其含义。
例子与影响：failure 只用于已观察到失败结果；定义清楚能减少分类混乱。
管理建议：我们定义

【可选 optional】
含义：允许材料未提供信息时跳过该字段。
例子与影响：强制字段会促使模型尽力给值；缺乏信息的材料需要测试其行为。
管理建议：一般优先允许缺失

【+ 标签／同时存为 Tag】
含义：识别出的分类值还写入普通 tags。
例子与影响：之后可以按 outcome:failure 筛选记忆；也会影响采用标签的整理范围。
管理建议：插件和词表协同设计

【添加字段／值、删除、嵌套字段】
含义：编辑结构及候选。
例子与影响：规则变化通常主要影响后续提取；旧材料需要安排重新处理。
管理建议：我们维护

19. 配置 → 观察：每项含义
================================================
这里控制从事实中形成持续认识。界面的“启用观察”开关控制该能力；独立的自动整合开关在 API 中另有字段。

【启用观察】
含义：允许这个 Bank 产生和维护 observation。
例子与影响：关闭会停止该库的观察整理，包括手动整理；事实仍可保存和召回。
管理建议：我们配置

【LLM 批大小】
含义：一次整理模型调用放入多少条新事实，当前为 8。
例子与影响：它控制批处理粒度；对话多久提交一次由 Sagitta 插件决定。
管理建议：先默认

【整合策略／默认／添加策略】
含义：为不同标签范围设不同的整理任务和上限。
例子与影响：例如通用管理范围偏重长期方法，项目范围保留阶段决策。
管理建议：我们定义

【策略名称】
含义：方便识别这套范围规则。
例子与影响：名称本身不成为一种记忆类型。
管理建议：我们定义

【适用范围：添加规则、标签、全部／恰好】
含义：定义哪些 observation scope 使用该策略，可用标签模式匹配。
例子与影响：一条规则里的标签要共同匹配；规则之间任意一条成立即可。
管理建议：我们定义

【优先级、前移、后移】
含义：多个策略都匹配时，排在最前的策略生效。
例子与影响：策略之间不相互拼接；匹配策略的空项退回“默认”。
管理建议：我们定义

【匹配范围数／已由更早策略处理】
含义：预览现有范围会落到哪套策略。
例子与影响：没有现有匹配也可能对未来新数据生效；检查是否规则写错。
管理建议：调试

【使命】
含义：说明应归纳什么、保留哪些条件。
例子与影响：它可以替换内置整理规则，和 Retain 的补充使命作用不同。
管理建议：我们审查

【每个范围的最大观察数】
含义：限定一个 scope 最多保留多少条派生认识，当前 -1 表示无限制。
例子与影响：有限上限会影响整理时如何合并和保留内容；它不是质量保证或遗忘策略的完整替代。
管理建议：我们实测后设置

【来源事实最大 Token 数】
含义：整理时给历史 observation 携带的支持事实总预算，当前 4096。
例子与影响：用于核对旧认识，避免只看总结；更大消耗更多上下文。
管理建议：我们定预算

【每条观察的来源事实最大 Token 数】
含义：每条旧 observation 的支持事实各有一个子预算，当前 256。
例子与影响：避免单条观察的许多证据占满总预算；必要时调大。
管理建议：我们定预算

【策略里的同名设置】
含义：只针对匹配范围覆盖使命、观察上限和来源事实预算。
例子与影响：留空按默认处理。
管理建议：我们配置

【预览提示词】
含义：查看默认规则、使命和本次材料怎样组合。
例子与影响：需要用真实样本检查逻辑与输出。
管理建议：调试

28. 四个实际阅读与维护例子
================================================
这些是使用流程示例，适合配合本地虚构演示库查看。

【想确认它有没有记住一个约定】
含义：到文档找原话 → 到记忆看提取事实 → 到观察看是否合并改变了条件 → 到页面看整理后的说法。
例子与影响：如果原文是“这次部署前确认”，检查每层是否保留“这次”。
管理建议：按来源逐层核对

【发现页面结论错误】
含义：打开生成依据 → 找到错误来自原文、提取还是归纳 → 修正对应来源 → 等整理／申请刷新页面。
例子与影响：只重写源查询可能改变表达，未必修复错误事实。
管理建议：Agent 维护，系统重算

【想保留长期管理经验】
含义：记录行动、实际结果和适用条件 → 后台 observation 归纳 → 用专题问题整理管理经验页面 → 后续遇到相关任务时检索使用。
例子与影响：项目库经验要进入主库，需要上游选择并写入；Hindsight 在各自 Bank 内整理。
管理建议：后续 Sagitta 调度

【想判断改配置是否有帮助】
含义：保留同一组测试材料与查询，比较提取结果、来源覆盖、错误与费用，再决定是否调整。
例子与影响：数量、证据次数或图的密度可以辅助观察，效果要看实际问题能否答对并保留条件。
管理建议：我们评估

核对依据：https://hindsight.vectorize.io/faq

29. 与未来 sagitta-memory 的分工
================================================
本次只解释现有 Hindsight 控制台；以下是此前讨论的插件职责，尚待实现和确认。

【我们维护的规则】
含义：服务模型、提取与整理使命、Directives、预算、权限和默认模板。
例子与影响：规则可先使用默认，针对实际失败样本调整。
管理建议：人工审查

【Agent 运行中维护的对象】
含义：普通项目 Bank、写入材料、事实纠正、页面主题、来源范围、主动查询与刷新申请。
例子与影响：使用既定接口积累经验，发现系统机制问题反馈给用户。
管理建议：Agent

【插件自动维护的事项】
含义：记录游标、待提交队列、来源标识、Bank 路由、总注入预算、失败状态。
例子与影响：避免主模型每轮手工填写技术字段。
管理建议：sagitta-memory

【常态／项目／情景召回绑定】
含义：决定当前哪些 Bank 参与自动查询及注入侧重。
例子与影响：这层配置属于插件；当前 Hindsight 界面中的召回开关控制单库内部检索方式。
管理建议：插件＋Agent 在约束内管理

【自动记录频率与触发时点】
含义：何时收集一轮工作、多少材料提交一次、何时查询并注入。
例子与影响：它与 Hindsight 分块大小、LLM 整理批大小分别配置。
管理建议：插件注册规则

【主 AI 的行为约束】
含义：授权、项目切换和任务注册等由宿主与任务系统实施。
例子与影响：Hindsight 的 Reflect 指令只约束其内部分析调用。
管理建议：Sagitta 执行层
