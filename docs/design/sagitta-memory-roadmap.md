# Sagitta Memory 路线图

更新日期：2026 年 10 月 19 日。

先完成第一阶段的功能与接口设计，再按用户审查节奏逐步实现。当前路线图记录范围和未决问题；功能列入路线图不代表已经实现或授权一次性开发。具体决定以[讨论记录](sagitta-memory-discussion.md)为准。

## 当前设计范围

| 功能 | 目标 | 进入实现前需要明确 |
| --- | --- | --- |
| Bank 与任务联动 | base_id 常驻；有效项目授权对应 Bank；挂载任务激活触发点 | 激活、撤销、归档事件与权限接口 |
| 主动查询 | memory_recall 仅查指定 Bank，附 theme 目录索引；memory_reflect 深度分析 | 后端检索映射、返回长度、cursor、目录范围 |
| Theme 文件树 | mkdir、create、ls、update、rm、cat、mv | 最小 meta、目录删除语义、元信息与正文更新边界 |
| 主动资料导入 | 上传文字文档供后端提取整理 | 来源标识、大小限制、异步返回 |
| B1 工具指引 | 注入 Sagitta 自己的工具说明 | 内容和提醒频率 |
| B2 自动注入 | 新会话基础库、任务激活项目情报；reflect low | 查询上下文、重复激活和失败行为 |
| C1 自动记录 | AI 收尾后，多 Bank 场景选段分库；可读少量前文辅助判断 | 指代保留、稳定文档 ID、串行进度、重复与失败恢复 |
| C4 项目初始化 | 项目创建节点预建 theme | 主题模板与创建顺序 |
| C5 Theme 自动更新 | 按调用次数与时间条件可配置更新 | 计数事件、阈值组合、原生触发与适配调度分工 |
| 状态与运行接入 | 启用时挂载、必要日志、接 sagitta-manager 更新 | 是否暴露操作状态工具；启动／连接方式 |

## 后续扩展

### 情境提醒 memory_reminder

由情境触发相关长期约定或经验提醒，尤其发挥基础 Bank 的作用。待设计：情境信号、由谁设置提醒、匹配时点、注入方式、重复提醒控制与效果验证。

### 硬 refresh

处理当前知识中的过时、重复和矛盾信息，维护有效认识。与正常 theme auto-update 分开。待设计：证据依据、历史事实与当前状态区分、更正／失效操作、不可判定冲突、来源再提取、派生内容更新及审计。Hindsight 页面 full refresh 本身不足以完成这些目标。

### 后台设置入口

memory_settings_show 与 memory_settings_edit。后续界定 AI 可以调整的运行策略及系统负责的配置，保持既有系统代码／提示词审查边界。

### 独立代码分析

考虑借鉴成熟分析方案提供 analysis 能力，结果由 Agent 选择上传到 memory。当前不照搬官方 Git 自动导入和后台代码调查。

## 待评估问题

- 如何发现长期积累但尚无 theme 覆盖的知识：已有主题管理能力，自动发现主题尚无确定方案。
- recall 每次附带目录时，如何在 theme 数量增长后保持上下文成本可控。
- 任务切换与跨 Bank 选段怎样保留必要指代，又避免向基础库灌入所有项目历史。
- 通过黑盒案例验证 a→否定 a→改 b、远距离指代、跨项目插话、更正与重复提交。
