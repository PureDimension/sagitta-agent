# Sagitta 后续开发方向与脚手架调研

日期：2026-10-26。状态：调研和开发顺序建议，供讨论；未授权实施下列全部功能。

## 判断与范围

保留 DSH 为运行宿主，Sagitta 负责跨任务的工作关联、结果处理、复查与长期经验应用。成熟项目可提供运行组件和机制参考；不以同时嵌入多个 Agent 框架作为默认路线。

此前建议停止横向建设，指限制无当前消费者的扩展，不撤销用户已确认的 claimId、任务关联与记忆设计。执行记录在监督开始消费后具有直接用途；采用原生日志及最小关联即可开始。

源码和归档核对以当前维护目录、archive/legacy-2026-10-15 及既有审查记录为依据。旧文档的完成声明不等于当前实现事实。上游资料为检索当日官方文档；未安装或运行所调研框架，未声称其长期效果已得到本项目验证。

## 外部脚手架与机制

### Paperclip：任务交接和外部工作管理

官方项目提供任务、Agent、执行适配器和运行记录。Skill 的工作流程要求 checkout，修改任务时关联 run ID；完成、阻塞、交接写回任务。它包含部分需要模型遵循的流程，不能把整个产品描述为全由代码强制。

Task Watchdog 在被监看的任务树全部停下且没有继续路径时唤醒检查 Agent，核查完成和阻塞并恢复工作；它有停止状态去重。这个机制不等同于运行中定期检查语义偏离。官方文档还将无输出监视和任务存活恢复与之区分。

官方可用 Process/HTTP 等适配器；本轮未发现或验证 DSH 专用适配。作为外部服务接入需要新增适配，而且要明确由 Paperclip 还是 Sagitta 的任务库作为权威。

建议：作为首要机制参考，借鉴任务/执行分离、交接记录、结果检查、明确唤醒原因。整套采用会引入公司组织、预算、服务/UI 和另一套任务状态，当前不建议默认接入。

来源：[项目](https://github.com/paperclipai/paperclip)、[工作协议](https://github.com/paperclipai/paperclip/blob/master/skills/paperclip/SKILL.md)、[适配器](https://docs.paperclip.ing/guides/org/agent-adapters/)、[Watchdog](https://docs.paperclip.ing/guides/projects-workflow/task-watchdogs/)。

### OpenClaw：周期思考与事件唤醒

Heartbeat 是调度触发的 Agent 回合，可使用独立上下文和模型；无事时静默，忙碌时推迟或跳过，运行和外部通知分开控制。其机制接近归档的续推，但包含多渠道 Gateway 和自身会话体系。

建议：借鉴安静返回、事件及时唤醒、周期兜底、忙碌合并及独立复查上下文；不把整套 Gateway 嵌入 DSH。周期执行本身不会自动形成可靠的多项目规划。

来源：[Heartbeat](https://docs.openclaw.ai/heartbeat)、[Automation](https://docs.openclaw.ai/cli/tasks)。

### Deep Agents / LangGraph：另一套完整运行框架

Deep Agents 提供文件上下文、子 Agent、压缩和人工交互；异步子 Agent 面向 Agent Protocol 服务，支持启动、更新、取消及独立线程。LangGraph 将会话级 checkpoint 与跨线程 store 分开。

建议：借鉴线程状态和长期资料分离。对 DSH 再加完整框架会重复维护运行循环、工具、消息和持久化，当前收益不足；checkpoint 也不能直接恢复任意已经启动的 Codex 进程。

来源：[Deep Agents](https://docs.langchain.com/oss/javascript/deepagents/overview)、[异步子 Agent](https://docs.langchain.com/oss/javascript/deepagents/async-subagents)、[持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence)。

### Mastra：后台记忆加工的具体参考

Observational Memory 使用后台 Observer 压缩新增对话，Reflector 在观察积累后再整理。它处理长期上下文维护，不等同于判断项目方向的监督员；压缩后的长期保真也不能从架构推出。

建议：可借鉴后台预处理和增量读取方式；当前不新增第二个记忆后端。DSH 接入其 memory 包仍需处理消息、存储与注入适配，不能视为现成插件。

来源：[Memory](https://mastra.ai/docs/memory/overview)、[Observational Memory](https://mastra.ai/docs/memory/observational-memory)。

### Hindsight / Letta：记忆后端与经验整理

Hindsight 继续作为已讨论的独立记忆服务方向，以实际部署版本 API 为准。它承担材料提取、检索、整理等能力，任务授权、执行监管与工作调度仍需 Sagitta 负责。

Letta 当前公开文档包含后台 dreaming、记忆检查和重组，可借鉴经验维护流程。它的完整 Agent/上下文体系不同于仅引入记忆服务；本轮不据文档宣传推断几个月的稳定成长效果，也不直接替换已讨论的 Hindsight。

来源：[Hindsight API](https://hindsight.vectorize.io/developer/api/retain)、[Letta Memory & dreaming](https://docs.letta.com/configuration/memory)。

### Langfuse：可选的开发观测平台

提供模型请求、工具和检索的 tracing、耗时与用量等观测。需要埋点或受支持的集成，无法自动取得官方 Codex 后端未暴露的内部事件。

建议：以后需要查看调用树时可以接；第一轮继续使用 DSH 日志及最小执行关联。它不承担任务业务和记忆管理。

来源：[Observability](https://langfuse.com/docs/observability/overview)。

## 开发顺序建议

1. 一批做清任务授权与派发契约。任务插件公开 claimId 校验，业务执行通过统一入口关联 taskId/projectId/claimId；绿色通道独立。子 Agent ID 与 run ID 使用官方身份。此处先设计清楚，再遵循逐批审查编写。
2. 接 DSH 原生异步委派并保存最小执行关联、输入/结果引用和任务依据快照。收到结果后投递主 Agent，让其检查产物并决定返工、推进其他任务或请求人。一次委派结束不自动完成业务任务。Codex 一次性后端与续聊扩展分开列出。
3. 恢复最小自主推进：有可推进任务时唤醒，已有执行在跑时等待或换任务，需要人时留问题，全部等待时静默。由确定事件触发主回合，周期只兜底；不得与 DSH 续行驱动并行制造重复回合。
4. 加独立复查会话，先消费前述任务、执行证据与近期对话。定期和必要结果节点检查偏离、停滞与重组；复查者和主 Agent 可互相发送质询/说明，结论可追溯。它通过既定接口影响工作，不能改系统代码或约束。
5. 接 sagitta-memory 的首批能力：基础/项目 Bank、交接/结果材料写入、主动查询与反思、激活时注入。保留用户已讨论的 Theme 和自动分库方向，后续逐项展开。任务/执行事实使用业务存储，记忆保存其派生认识和经验，避免后台总结覆盖权威状态。

这个顺序先让监督有证据和执行入口，再让记忆整理真实工作经历。它不要求先做完整日志平台、全目录文件快照、自动任务分解、组织树、预算系统或新管理 UI。

## 第一轮应当具备的使用行为

同时接到 A、B 两项工作；Sagitta 为 A 派子 Agent，等待时推进 B；A 返回后检查产物并提出具体返工；真正需要用户判断时保留问题，其他任务继续；用户回归能看到完成内容、结果依据与待决问题。独立复查者随后可以指出遗漏或要求说明，并收到主 Agent 的回复。

这里的业务步骤保持开放，由模型根据任务决定；代码固定授权、归属、执行生命周期和投递机制。尚待用户审查确定具体接口和通知规则。
