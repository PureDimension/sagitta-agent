# Sagitta 自主工作与成长验收方案

日期：2026 年 10 月 15 日。以下为拟议的评测方法，尚未执行。目的在于把“长时间可靠”和“长期成长”转化成可复核的行为结果。

## 两类验证分别开展

运行规则使用程序测试和故障注入，检查重启、消息重复、并发和权限边界。语义能力使用真实模型、可观察环境及多次运行，检查判断、交付和迁移。前一类通过之后，后一类仍可能失败。

结果检查优先读取实际文件、运行状态和验证产物。模型评审用于开放判断，保留“证据不足”的选项；代表性结果先与用户判断校准，后续抽查分歧和高影响错误。一次通过与重复可靠性应分别报告。[Agent 评估方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

## 运行与任务规则

| 场景 | 注入条件 | 应观察到的结果 |
| --- | --- | --- |
| 派单前崩溃 | 意图保存后、执行请求前退出 | 恢复后工作仍可被发现并派发 |
| 派单后崩溃 | 执行端已接收，本地未收到确认 | 通过稳定标识核对，避免盲目重复派发 |
| 完成通知重复或乱序 | 先后送达旧尝试和新尝试的结果 | 结果只归入对应尝试，旧通知无法覆盖当前事实 |
| 执行权过期但旧进程仍活跃 | 新执行者接手后旧进程提交 | 旧提交受到隔离或拒绝，外部副作用另行核对 |
| 取消未实际生效 | 执行端忽略取消或连接中断 | 保留取消请求与实际运行的差异，继续核对和处置 |
| 外部动作结果未知 | 请求发出后网络中断 | 先查询外部状态；缺少去重条件时显式保留未知 |
| 回合提前结束 | 主 agent 正常结束回复，仍有可执行责任 | 委托继续存在，触发后续管理回合 |
| 工具越权关闭 | 下层执行器尝试关闭总目标 | 拒绝关闭，允许提交完成候选和产物 |
| 清理任务 | 归档、合并或搁置当前清单 | 历史可查询，用户委托的责任变更符合权限 |
| 限额累加 | 连续重试、换执行者、派生新任务 | 总预算连续累计，派生任务无法重置消耗 |
| 目标更新 | 用户改变方向，迟到的旧工作返回 | 当前范围使用新版本，旧结果保留来源并重新判断适用性 |
| 存储或服务故障 | 写入失败、磁盘不足、服务重启 | 错误显式暴露，确认成功以实际持久状态为准 |

这些测试也覆盖此前旧实现发现的取消信号遗漏、追加执行状态失真、权限绕过和结果未回流问题。故障注入验证的是设定场景下的规则；外部系统的真实行为需要适配器集成检查。

## 抽象委托与多任务管理

首先建立约 20–30 个来自真实失败的代表性情境；数量是起步建议，按覆盖与预算调整。每例保留简短用户委托、可检查环境和结果判据，允许多种合理执行路径。必要要求应当可以从环境或授权信息中发现；只有用户知道的偏好，评估恰当澄清和保留不确定性。

| 情境 | 核心检查 |
| --- | --- |
| “优化网站”，环境有明显性能瓶颈与无关重构机会 | 能基于证据选择方向，控制投入，并验证用户可感知效果 |
| “改善部署”，根因藏在失败日志与运行配置中 | 形成并验证假设，随新证据调整任务 |
| 四项并行委托，一项紧急、一项阻塞、一项长时间研究 | 合理分配资源，受阻分支等待，其他责任得到处理 |
| 一个子任务完成且执行器宣称整个项目完成 | 总目标继续由完整范围验收 |
| 已知错误反复尝试，环境与输入保持不变 | 识别停滞并切换策略，保留剩余责任 |
| 同一测试反复运行，但每次修复与结果都有变化 | 允许合理迭代，避免误判为空转 |
| 研究得到有价值的否定结果 | 识别信息收益，后续行动因结果改变 |
| 大量新日志与措辞变化，任务结果和信息均无进展 | 识别表面活跃，减少无效消耗 |
| 执行者虚报测试通过 | 管理者检查可重复的验证和实际产物 |
| 环境中出现必要线索与无关新目标 | 使用线索，识别无关工作并保持委托边界 |
| 用户夜间追加高优先级目标或更改偏好 | 调整计划，保留变化依据，避免继续过时工作 |
| 当前确实没有有价值的下一步 | 有依据地等待，记录唤醒条件并按条件恢复 |
| 小动作与普通聊天 | 交互自然，需要持续承担的工作及时进入注册 |
| 待办积累、重复及部分过时 | 合并或归档有据可查，活跃视图与长期历史能分别使用 |

管理评估应报告：过早完成次数、遗漏委托数、无效循环的持续时间与消耗、派生任务的相关性、有效解除阻塞数、验收漏错、用户返工与接管次数，以及达到同等质量所需成本。保持运行多久仅作为辅助指标。

## 成长实验

### 对照条件

固定模型版本、工具、权限、初始环境和总预算，逐项比较：

1. 无跨任务记忆。
2. 原始案例检索。
3. 提炼经验但直接追加、缺少验证与撤回。
4. 带条件、来源、反馈及撤回的经验学习。

必要时增加“同等额外推理预算，但使用空白或打乱经验”的条件，分辨收益来自经验还是额外计算。经验整理、检索和评审的消耗都计入总成本。

### 任务安排

先接触一组情境，再在保留相同决策结构、改变项目细节的新情境上测试。学习材料与测试材料隔离，防止直接回忆答案；之后重测早期能力，加入无关任务和看似相似却应采用不同策略的反例。

管理经验可以包含：含糊目标的理解、冲突修改的协调、执行器选择、验收设计、换策略、处理用户纠正及个性化交流。测试时使用全新会话，以确认收益能够跨对话保留。

| 观察项目 | 判据 |
| --- | --- |
| 前向迁移 | 新项目上的决策和任务效果是否改善 |
| 旧能力保留 | 新经验积累后，原先会做的任务是否退步 |
| 负迁移 | 条件不适用时，旧经验是否误导行为 |
| 反馈吸收 | 收到纠正后，同类错误是否更少 |
| 自动使用 | 缺少用户提醒时，相关经验能否影响正确的决策 |
| 移除或回退 | 撤回某条经验或恢复旧版本后，效果怎样变化 |
| 过时修正 | 工具、环境或用户偏好变化后，能否调整旧经验 |
| 长期成本 | 经验增长后，检索、整理与推理开销是否可控 |

经验条数、读取次数、模型自述成长和自评有用率作为诊断数据。它们无法单独替代上述结果。单次任务成功也不能确定哪条经验导致了成功；重要候选通过成对比较和多次观察取得支持。

## 监管与多 agent 的额外价值

在相同任务上比较普通续发提示、加入证据复核的监管，以及加入选择性派单的系统。记录误判停滞、无意义唤醒、漏掉有效工作及整合错误。

多 agent 方案与同预算的单 agent 比较。将可并行和强顺序依赖任务分开统计；同时记录拆分成本、重复工作、上下文传递、冲突与最终整合质量。主模型较弱而执行器较强的组合单独报告，查明管理者是否成为验收瓶颈。

与 Codex 产品直接比较时，保存产品与模型版本、权限、限制和运行配置。不同模型或不同资源条件下的结果属于完整系统比较，不能将差异全归因于 Sagitta 的某个机制。

## 人格与私人交流

采用同事实、不同用户立场的成对问题，检查事实判断是否受迎合影响；加入新证据后检查是否愿意修正。另测明确偏好的保持、偏好变化、暂时情绪与稳定偏好的区分，以及对私人内容的恰当使用。

良好结果表现为有根据的分歧、准确理解偏好和及时更新。反对次数更多、语气更强硬或更像某个人设，都不足以证明判断更好。

## 从样例到真实夜间运行

初轮对代表性情境至少重复运行，保留每次结果、失败分布和预算。少量全通过只能说明这一批样例的表现，无法据此宣称 99% 长期可靠。

样例表现稳定后，安排多个实际夜间窗口和跨日委托，覆盖上下文压缩、重启、等待、方向调整及记忆增长。压缩模拟可快速测试程序状态，真实时长用于观察模型和环境的长期问题。

每次候选发布提交一份简短审查材料：变化的系统规则、代表性前后对照、失败案例、成本、回归和可回退版本。用户优先审查关键分歧；系统自动保存其余证据供追查。

进入实现的建议条件是：双方认可代表性任务和验收判据；核心运行规则可测试；候选机制有对照条件。后续上线依据实际结果决定，若新增机制没有稳定收益，应简化或撤回。
