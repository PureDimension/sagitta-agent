# Sagitta 模块职责讨论

## 已确认的目标与边界

核心目标是可靠地自主推进多个长期任务，并从真实工作效果中形成跨对话的成长；长期成长是用户特别重视的能力，独立想法与人格放在后续完善。具体执行工作可以交给下层 AI，Sagitta 主要学习意图理解、策略选择、派单、监督和验收。

用户主导方向冲突的取舍。Sagitta 可以自主使用既定系统和调整工作策略；程序、核心提示词及系统约束的改变由用户审查。经验内容可以在既定机制中演化，经验与任务数据受到系统约束。

下文是职责划分建议。任务状态、注册触发条件、清理规则、成长算法和实际插件包数量继续讨论。

## 四项能力的关系

任务、记忆、异步执行和监管都需要保留。它们分别回答四个问题：要持续负责什么及怎样分配工作；过去经历对这次判断有什么帮助；实际工作是否仍在运行及产出了什么；既定责任是否得到有效推进。

| 能力 | 建议职责 | 与其他能力的关系 |
| --- | --- | --- |
| 任务与多任务编排 | 长期目标、注册约束、计划变化、依赖、资源分配、任务历史和结果 | 任务状态与调度的事实来源；清理当前清单时保留可查询的档案 |
| 记忆与成长 | 从工作和对话中提炼、检索、修正经验，观察后续使用效果 | 读取任务结果及来源；为管理判断提供参考 |
| 异步执行 | 执行 AI 与工具的启动、状态、输出、取消和结束通知 | 运行记录关联所属任务；执行结束后进入结果检查 |
| 自主推进与监管 | 观察运行及进度证据，唤醒管理回合，发现停滞和异常并触发纠偏 | 使用任务事实、经验与执行状态；与 DSH 的续行驱动协调 |

任务完成、执行结束和经验成立分别需要各自的判断。任务事实由任务能力维护，运行事实由执行能力提供，经验保留来源与适用条件。

## 旧插件的调整建议

| 旧插件 | 建议方向 |
| --- | --- |
| memory | 拆出任务工具与注册门禁，专注记忆及成长；移除强制四流和个人称呼枚举的前提 |
| 新的任务模块 | 承接任务事实、历史、注册、结果和多任务编排；提供供监管和成长使用的接口 |
| auto-advance | 收敛为监管、唤醒和停滞处置；界面展示与底层读取独立；尽量复用 DSH 续行能力 |
| async-work | 优先由 DSH Jobs 承担运行状态与完成通知；保留必要的任务关联和持久运行摘要，具体差距通过原型核对 |
| codex-dispatch | 调整为可选执行器适配；按所需能力选择官方后端或薄扩展，核心任务语义与某个产品解耦 |
| manager | 按 2026-10-20 决定，负责单仓库更新、Sagitta 插件集中登记与预设装配；见 [Manager 接入约定](design/sagitta-manager.md) |

这些是逻辑边界，物理插件包以实际依赖和加载要求决定。首轮围绕任务、成长、执行和监管四项能力，验收与评估贯穿其中；共享连接作为基础支持。

## 需要明确补齐的职责

任务档案记录完整的语义变化与执行结果。当前任务视图、历史记录和经验检索各自按需要取用这些事实。暂停、搁置、合并、取消和恢复的具体规则留到任务机制讨论中确定。

结果检查为成长提供反馈：派单目标、实际产物、验证情况、用户后续纠正和返工记录应当能相互对应。首版在任务验收与执行记录之间落实这些职责，通过统一接口供成长读取；独立评审 agent 是否有价值需要具体场景验证。

## DSH 的承接范围

早期讨论以 `0.2.0-rc.2` 为基线；2026-10-20 新骨架目标固定为 `0.2.1-rc.2`，版本记录在根 `package.json`。实际运行兼容性仍须通过接入验证。配置、凭据、插件加载、标准后台工作及会话续行优先使用官方能力。

DSH Goal 的续行驱动面向同一会话，恢复会话后需要显式重新授权续行；默认 Jobs 实现随进程退出而结束。多任务选择、跨重启恢复、重试边界和完成效果判断仍需在 Sagitta 层明确。

参考：[Jobs](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.0-rc.2/packages/jobs/jobs/README.md)、[Goal 续行驱动](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.0-rc.2/packages/goal/goal-round-driver/README.md)。

## 后续讨论顺序

结合 [长期成长与自主工作调研](research/2026-10-15/conclusions.md)，先确定长期委托、执行证据和验收的关系，以及任务注册、清理与历史的边界。随后讨论结果如何转化为经验、经验怎样影响下一次工作。多任务编排归任务；监管与执行的唤醒、等待、重试和恢复分别明确。
